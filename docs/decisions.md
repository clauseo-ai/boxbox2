# decisions

every locked decision, the alternative it beat, and why. newest last.
a decision here is binding on the build. changing one means a new row that
supersedes it, never an edit in place. "v1" is boxbox's first version, a
separate private codebase. it is the source of the board's code and of the
lessons in `scars.md`.

| # | date | decision | beat | why |
|---|---|---|---|---|
| 1 | 2026-09-30 | **the board is frozen.** firmware, wire protocol v1, the three key-index maps, the four-verb grammar, the banks, the colours and every key's behaviour stay exactly as they are today. v2 is judged on the board by identical behaviour, not by parity of spirit | redesigning the board around the usage data (nearly all use sits in one bank, and the talk key is the most pressed) | the maintainer's call: full compatibility, exactly as it is now. the board is used daily for voice and for thread switching, and its green lights are read as indicators. usage data describes use; it does not license a change here |
| 2 | 2026-09-30 | **the board's bank and target names stay in telemetry** (drive, pit, grid, fleet, calc; talk, gauge, radio) even though the f1 language leaves the ui | renaming them with the rest of the f1 vocabulary | decision 1 plus the telemetry rule: existing names are never renamed, past data stays queryable |
| 3 | 2026-09-30 | **the f1 identity goes.** no pit wall, radio, powertrain, desk, stint, paddock, box box copy or visuals in the ui. the name boxbox stays | keeping the metaphor as flavour | the maintainer's call. the metaphor also made the ui harder to learn for anyone else, which matters for an open project (decision 6) |

| 6 | 2026-09-30 | **boxbox is open source and runs on other people's machines**, not only the maintainer's fleet. copy, onboarding and defaults are written for someone new to it, and the maintainer's fleet is a pattern in the docs, never a fixture | a personal instrument for one person (the v1 framing) | the maintainer, 2026-09-30. the tenancy shape was open at first and decision 10 settled it |

| 12 | 2026-09-30 | **the design direction is live windows.** home is the agents' actual work: every live thread is a window in its repo's colour carrying a live tail, and a window grows into its thread. delight is earned by real events, never decorative. how the direction maps to phone, ipad and mac is the design law in `design.md` | hush, folio, depth (boring); aurora, orbit (gimmicky); settle; lift (right motion, mundane look, pwa-invalid island) | the maintainer picked it after seven rejected directions, looking for personality, depth, excellent motion and nothing gimmicky. it is also the only direction whose home shows the work itself, which is what people open the app to check |

| 14 | 2026-09-30 | **the board keeps its v1 dependencies byte for byte.** the v2 repo holds `board/daemon/src/` (every file unchanged except `client.ts`) and `board/lib/` (the v1 files the board imports by relative path: `lib/board/contract.ts`, `lib/board/seats.ts`, `lib/read/contract.ts`, `lib/store/model.ts`, `lib/fleet/sse.ts`, and type-only modules for `BrainEvent`, `HostSnapshot`, `PendingItem`, `GlobalEventFrame`). the new `client.ts` translates v2's api into the `BrainEvent` shapes the daemon already consumes. refines 11 | rewriting the seat and binding code against v2 types; serving v1-shaped routes from the server | research: controller, scenes, state and render import `../../lib/...` directly, so "only client.ts changes" is only true if those files come along. keeping the translation inside the board keeps the server free of v1 shapes |

| 16 | 2026-09-30 | **a cursor at every hop, and the server computes the fleet once.** cmx2 seq, deduped by the server, re-sequenced into a bounded journal, resumed by the worker from indexeddb. needs, window order, read state and window tails are derived once in the server and rendered by every surface | client-side derivation and rest reconcile on reconnect (v1) | the reload habit, the disagreeing session lists and the drifting faults all trace to missing cursors and per-client derivation (`scars.md`) |
| 17 | 2026-09-30 | **`telemetry/schema.ts` stays the telemetry dictionary**; the rust ingest is generated from its json output with a drift test | moving the dictionary into rust and generating typescript from it | `schema.ts` is the single source of truth and the query tool reads it. keeping it avoids forking the dictionary that v1's logs were written against |
| 18 | 2026-09-30 | **server state lives in one sqlite file with one writer** (`boxbox.db`: read state, push subscriptions, prefs, bindings, devices, cursors); telemetry stays append-only ndjson | v1's scatter of json files written from many places | one owner, transactions, no torn writes, and nothing to reconcile across files |
