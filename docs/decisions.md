# decisions

every locked decision, the alternative it beat, and why. newest last.
a decision here is binding on the build. changing one means a new row that
supersedes it, never an edit in place. "v1" is boxbox's first version, a
separate private codebase. it is the source of the board's code and of the
lessons in `scars.md`.

| # | date | decision | beat | why |
|---|---|---|---|---|
| 1 | 2026-09-30 | **the board is frozen.** firmware, wire protocol v1, the three key-index maps, the four-verb grammar, the banks, the colours and every key's behaviour stay exactly as they are today. v2 is judged on the board by identical behaviour, not by parity of spirit | redesigning the board around the usage data (nearly all use sits in one bank, and the talk key is the most pressed) | the maintainer's call: full compatibility, exactly as it is now. the board is used daily for voice and for thread switching, and its green lights are read as indicators. usage data describes use; it does not license a change here |
| 2 | 2026-09-30 | **the board's bank and target names stay in telemetry** (drive, pit, grid, fleet, calc; talk, gauge, radio) even though the f1 language leaves the ui | renaming them with the rest of the f1 vocabulary | decision 1 plus the telemetry rule: existing names are never renamed, past data stays queryable |
| 3 | 2026-09-30 | **the f1 identity goes.** no pit wall, radio, powertrain, desk, stint, paddock, box box copy or visuals in the ui. the name boxbox stays | keeping the metaphor as flavour | the maintainer's call. the metaphor also made the ui harder to learn for anyone else, which matters for an open project (decision 6) |
| 4 | 2026-09-30 | **the ipad is a first-class device**, designed and verified at its own width, not a stretched phone | treating it as an afterthought because the usage log shows little tablet traffic | a tablet is used when travelling and on days it replaces the phone. a usage log measures the past, not the next months |
| 5 | 2026-09-30 | **permissions stay fully supported**: the inbox card, the push with actions, the board's pit digits | cutting permission support because the maintainer's own runs rarely raise one | the maintainer runs agents without permission prompts, but other people will run boxbox with permissions on. no use by one person is not no use |
| 6 | 2026-09-30 | **boxbox is open source and runs on other people's machines**, not only the maintainer's fleet. copy, onboarding and defaults are written for someone new to it, and the maintainer's fleet is a pattern in the docs, never a fixture | a personal instrument for one person (the v1 framing) | the maintainer, 2026-09-30. the tenancy shape was open at first and decision 10 settled it |
| 7 | 2026-09-30 | **push is the product.** reliable lock-screen delivery when no boxbox window is in front of the person, on phone, ipad and mac, for questions, permissions, real faults and "the turn you started is done". presence is per device and means "looking at it", never "a window exists somewhere" | v1's rule: mute every push while any client was visible in the last 90 s | v1's usage log showed almost no questions reaching a phone as a push, and long waits to answer the ones that did. a person who fires a prompt and walks away depends on push, so "done" is the push that matters most |
| 8 | 2026-09-30 | **the backend is rust**: one small binary on the vm (http, sse, websocket terminal relay, push, telemetry, read state, needs) | keeping a node/next server | the maintainer's preference, and v1's node server once wedged its vm by ballooning to about 10 gb on a reconnect resync. a single rust process with bounded buffers makes memory a design parameter instead of a surprise. cmx2 types come from cmx2's generated `openapi.json`, which carries every route and event schema, so no decoder is hand-written |
| 9 | 2026-09-30 | **gaps in cmx2 are asks, not workarounds.** cmx2 is being built now; anything boxbox needs from the daemon (event ids and replay first) goes in `docs/cmx2-asks.md` for that build to land | designing around a daemon that looks unfinished today | cmx2 was still being built, so its state at any moment is not final |
| 10 | 2026-09-30 | **one install per person, nothing shared.** each user runs their own boxbox against their own cmx2 daemons. single-user auth (password gate, pairing), no accounts, no shared state | one shared boxbox with accounts; own installs over a shared fleet | keeps auth, read state and push single-tenant, and matches cmx2's own pairing model |
| 11 | 2026-09-30 | **the board daemon's transport is ported; nothing else on the board changes.** only `board/src/client.ts` (the file that talks to the server) is rewritten against v2's api. firmware, protocol, render, scenes, verbs, controller and keymaps are carried over byte for byte. a trace recorded against v1 (keys in, calls and led frames out) is replayed against v2 and must match | the v2 server serving v1's board routes and event stream forever | the maintainer picked it. v2 carries no v1-shaped adapter, and the recorded trace holds decision 1 to "identical behaviour" mechanically |
| 12 | 2026-09-30 | **the design direction is live windows.** home is the agents' actual work: every live thread is a window in its repo's colour carrying a live tail, and a window grows into its thread. delight is earned by real events, never decorative. how the direction maps to phone, ipad and mac is the design law in `design.md` | hush, folio, depth (boring); aurora, orbit (gimmicky); settle; lift (right motion, mundane look, pwa-invalid island) | the maintainer picked it after seven rejected directions, looking for personality, depth, excellent motion and nothing gimmicky. it is also the only direction whose home shows the work itself, which is what people open the app to check |
| 13 | 2026-09-30 | **the standard of care is the same for everything.** it applies to the code, the rust backend, the frontend, the tests, the logs and the parts nobody sees, not only the ui. performance and memory are design parameters with numeric budgets and gates on both sides (`architecture.md`, `verification.md`), never an afterthought. no hacks, no "good enough for now" | a personal project held to a side-project bar, polish deferred to later | an open project is judged by its code as much as by its screens, and both stay fast and bounded in memory. v1 wedged its vm by ballooning about 10 gb on a resync; that class of failure is designed out, not patched |
| 14 | 2026-09-30 | **the board keeps its v1 dependencies byte for byte.** the v2 repo holds `board/daemon/src/` (every file unchanged except `client.ts`) and `board/lib/` (the v1 files the board imports by relative path: `lib/board/contract.ts`, `lib/board/seats.ts`, `lib/read/contract.ts`, `lib/store/model.ts`, `lib/fleet/sse.ts`, and type-only modules for `BrainEvent`, `HostSnapshot`, `PendingItem`, `GlobalEventFrame`). the new `client.ts` translates v2's api into the `BrainEvent` shapes the daemon already consumes. refines 11 | rewriting the seat and binding code against v2 types; serving v1-shaped routes from the server | research: controller, scenes, state and render import `../../lib/...` directly, so "only client.ts changes" is only true if those files come along. keeping the translation inside the board keeps the server free of v1 shapes |
| 15 | 2026-09-30 | **the frontend is typescript, solid and vite: a static spa embedded in the rust binary, no ssr.** a dedicated web worker owns the stream, the cursor, the reducer and indexeddb, and posts patches to the ui once a frame | react (vdom diffing per streamed delta, v1's perf scars); svelte 5 (close second); no framework (a hand-rolled reactive layer at app scale) | fine-grained updates suit a ui that is mostly streaming text and rolling numbers; the worker keeps parsing and storage off the thread that scrolls. the maintainer left the frontend choice open |
| 16 | 2026-09-30 | **a cursor at every hop, and the server computes the fleet once.** cmx2 seq, deduped by the server, re-sequenced into a bounded journal, resumed by the worker from indexeddb. needs, window order, read state and window tails are derived once in the server and rendered by every surface | client-side derivation and rest reconcile on reconnect (v1) | the reload habit, the disagreeing session lists and the drifting faults all trace to missing cursors and per-client derivation (`scars.md`) |
| 17 | 2026-09-30 | **`telemetry/schema.ts` stays the telemetry dictionary**; the rust ingest is generated from its json output with a drift test | moving the dictionary into rust and generating typescript from it | `schema.ts` is the single source of truth and the query tool reads it. keeping it avoids forking the dictionary that v1's logs were written against |
| 18 | 2026-09-30 | **server state lives in one sqlite file with one writer** (`boxbox.db`: read state, push subscriptions, prefs, bindings, devices, cursors); telemetry stays append-only ndjson | v1's scatter of json files written from many places | one owner, transactions, no torn writes, and nothing to reconcile across files |
| 19 | 2026-09-30 | **the ios viewport law carries over from v1's scars**: no `viewport-fit=cover`, `html` never scrolls, inputs 16 px or larger on touch, the keyboard inset only while an editable holds focus, safe-area insets always floored, no after-the-fact scroll snapping | re-deriving it on the phone | v1 lost a week to six ios keyboard lies; the last one was `viewport-fit=cover` leaving a dead 62 px band on ios 27 (`scars.md`) |
| 20 | 2026-09-30 | **boxbox builds against a pinned cmx2.** `cmx2.pin` holds one commit; `openapi.json` and the manifest are vendored from it; the dev daemon runs from it on 4840 to 4849 and the boxbox dev server on 3001. gaps go to cmx2's `docs/engineering/ASKS.md` as unassigned rows, never around. m1 needs only what the pin serves; m2 starts when ASKS a1 to a3 land | building against cmx2's moving working tree; a dev daemon from the working tree | a pin makes every build reproducible while cmx2 is mid-build, keeps boxbox's generated types honest, and makes moving to a new contract a visible, checked step |
| 21 | 2026-09-30 | **the board's carried files drop the maintainer's names.** v1's board names the maintainer's machines (a default `machineOrder` in `src/config.ts`, host keys in three tests) and a tailnet origin (`install.sh`). in v2 those literals become placeholders (`[]`, `h1` to `h3`, `https://<vm>.<tailnet>.ts.net`). the real values live in the board's own config file, which overrides the default, so the board behaves identically for its user. `board/CHECKSUMS` marks each such file `scrubbed`, and the checksum test re-derives it from v1's bytes through a substitution file only the maintainer holds. refines 14 | carrying the names byte for byte into a public repo | rule 12 and the m0 goal: nothing machine-specific in the repo. the config file already wins over the default, so decision 1's "identical behaviour" holds |
| 22 | 2026-09-30 | **the bench's model is scripted, the daemon is real.** `just cmx2` points the pinned daemon's anthropic provider at `bench/model.ts`, which answers the messages api with a script picked by a marker in the prompt (tools, a question, a stream of n words). every event, route, tool call, ask and queue boxbox sees is the real daemon's | a real provider for the scripted session | a real model cannot be made to ask the same question or stream a thousand deltas on cue, costs money per run, and needs a real key in the bench (the bench's environment is an allowlist precisely so no key leaks in). rule 4 is about boxbox's integration: the daemon is never mocked |
| 23 | 2026-10-01 | **presence means visible and focused within 90 s.** a device is looking when its last report said boxbox was visible and focused and that report is under 90 s old; a thread is watched when a looking device has it on stage or its window in view. refines 7; supersedes "input in the last 2 minutes" in `design.md` and `architecture.md` | "visible, showing the thread, with input in the last 2 minutes" | presence per device means "looking at it", visible and focused within 90 s, never "a window exists" (decided in the push milestone, 2026-10-01). focus is what the platforms report honestly on every device; input timing needs listeners on every surface and still counts a mac left focused on a desk as present for two minutes |
